Estado actual:
Módulos 1-16 documentados y catalogados en el core. M17-M20 quedan reservados con nombre oficial para expansión futura, sin declararse funcionales todavía.

Este proyecto no debe improvisarse.

LaIA/Mistral y Hermes Agent deben arrancar con Knowledge Bootstrap local. Ojo de Dios v1 no se considera completo si la precarga/refresco de conocimiento, context packs, JSON validado y panel de estado IA/Hermes Agent no están definidos e implementables. Fine-tuning no es requisito inicial; primero RAG local, embeddings, memoria estructurada, EvidenceStore, ScoringEngine y X5/OjoRouter.

Resumen:

- Ojo de Dios es una plataforma ofensiva modular local de auditoría interna autorizada/laboratorio.
- La doctrina autorizada exige demostrar con evidencia hasta dónde puede llegar un atacante dentro de activos propios o expresamente autorizados.
- Tiene 16 módulos oficiales.
- X5/OjoRouter manda la ejecución y orquestación.
- LaIA/Mistral es cerebro operativo, no adorno.
- Hermes Agent Lab evoluciona el sistema en sandbox como manos operativas constructoras dentro de `modules/laboratory/`.
- Hermes Agent oficial: `https://github.com/NousResearch/hermes-agent`; documentación: `https://hermes-agent.nousresearch.com/docs/`.
- Hermes Agent usa DeepSeek Pro como modelo principal de calidad; DeepSeek Flash queda reservado para healthcheck, resumen rápido, clasificación simple o fallback.
- EvidenceStore demuestra lo ocurrido.
- ScoringEngine aprende de resultados.
- VersionLock fija herramientas/versiones.
- Attack Surface Graph conecta servicios, versiones, CVEs, técnicas y evidencias.
- X4/Cantera IQ se aprovecha como referencia y conector de scraping.
- X5 existente se aprovecha como referencia arquitectónica.
- Las técnicas pendientes quedan como IMPLEMENTACION_USUARIO_REQUERIDA.
- LaIA/Hermes Agent ingieren conocimiento mediante Knowledge Base local, RAG, context packs, registry, ToolHealth, VersionLock, EvidenceStore, ScoringEngine, CVE intelligence y propuestas Hermes Agent, no por prompt gigante ni por fine-tuning inicial.
- Si fuentes contradicen, manda `docs/KNOWLEDGE_SOURCE_PRECEDENCE.md`.
- CVE, Kali tools y evolución Hermes se documentan como conocimiento controlado, no como funcionalidad ejecutable automática.
- No se finge funcionalidad.
- No se eliminan técnicas.
- No se sustituyen técnicas.
- No se crean tests por palabras, categorías o juicios externos.
- Los tests solo validan funcionalidad real, contratos, seguridad de ejecución, permisos, evidencia, estados honestos y ampliabilidad; nunca conteos rígidos.
- Mano de Dios es un producto separado y no se integra dentro de Ojo de Dios.
- DeepSeekAssist/Hermes Tool Adoption, CVE-to-Technique, Supply Chain Sandbox, AI Research Gates y Decision Log forman parte del diseño base de Ojo de Dios v0.1 Lab Core, no de una versión 2.
- El registry de Ojo de Dios es dinámico: el número total de técnicas es métrica informativa, no condición bloqueante.

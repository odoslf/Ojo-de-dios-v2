# CODEX WORKING RULES — OJO DE DIOS

## Reglas

- No improvisar arquitectura.
- No cambiar módulos.
- No cambiar Módulo 9.
- No crear módulo DNS independiente.
- No eliminar técnicas.
- No sustituir herramientas por versiones más suaves.
- No crear tests por palabras o categorías.
- No registrar técnicas genéricas sin fields propios.
- No marcar stubs como funcionales.
- No ocultar IMPLEMENTACION_USUARIO_REQUERIDA.
- No tocar lógica privada.
- No instalar dependencias salvo ronda específica.
- No modificar requirements salvo ronda específica.
- No ejecutar herramientas externas salvo ronda específica.

## Cada ronda debe responder

- archivos creados;
- archivos modificados;
- resumen;
- tests/comandos ejecutados si aplica;
- qué queda pendiente;
- si tocó lógica funcional o no.

## Política de cambios

Cambios pequeños.
Rondas acotadas.
Sin reescrituras gigantes.
Sin mezclar documentación, DB, UI, IA y módulos en una sola ronda salvo orden expresa.
